# 用户流程

```text
BOM 管理 / 当前打开 BOM 视图
  └─ 选中车型级物料
      └─ 点击【转量产】
          ├─ 校验部品番号：^\w*-(?:1|2)-\w*$
          │   └─ 不通过：提示“仅可对车型进行转量产！！”
          └─ 通过：以车型编码前三位组织匹配规则并扫描当前 BOM
              └─ 弹出【待转码物料清单】
                  ├─ 展示匹配项、建议量产编码、BOM 层级及纳入/排除原因
                  ├─ 仅两列清单导出（列名待确认）
                  └─ 用户确认
                      └─ 二次确认高风险操作
                          └─ 后端顺序（待技术确认）
                              1. 保存试制状态基线
                              2. 另存创建量产物料
                              3. 当前视图内结构替换
                              4. 插入颜色表记录
                              5. 调用 SAP 颜色接口
                              6. 记录审计与结果
```

## 组件与样式引用及适用性

### 原型信息架构

- **左侧：BOM 树**。提供当前 BOM 语境和明确的车型节点选择，不将“转量产”暴露为脱离上下文的全局动作。
- **顶部操作栏：浏览操作 + 其他操作下拉菜单**。与实际 BOM 管理页面分组菜单一致；将新入口置于“其他操作 → 试制转量产”。只有已选车型节点时可用，不符合时以就近错误信息提示。
- **中心：结构明细表**。展示层级、物料编码、名称、数量及转码判定，便于用户在开启操作前判断影响范围。
- **第一层弹窗：待转码物料清单**。匹配物料全量展示、不可逐项取消；展示已确认的演示量产编码，并固定导出原物料编码/原物料名称两列。
- **第二层确认弹窗：演示边界确认**。只确认编码规则演示，不纳入基线、物料创建/替换、颜色表或 SAP。
- **执行结果：规则演示摘要**。不代表服务端事务或真实业务执行。

### 视觉与交互原则

- **运行时 + 源码 Candidate 样式/挂载证据**：已在 DEV 蓝色主题下复现产品数据管理 → BOM管理，并用唯一编号 `12100-2CB -A401` 加载气缸体总成；初始 Process1 经“切换视图”后为 Design。采用 12px 微软雅黑字体、浅灰分隔线、树/网格工作区、紧凑工具栏与菜单分组。源码已确认 `ProductBOM → PseBomMenu → BOMCommon` 链，目标放入 `BOMCommon` 以呈现于运行时“其他操作”。证据见 `analysis/evidence/20260915-ext001-pse-bom-menu-source-summary.md`。
- 该 Candidate 仅用于当前原型视觉适配与菜单定位；未验证其他主题/角色，且运行时“其他操作”和标准源字典“通用操作”存在待解释差异，不将其表述为 Verified。
- 所有交互使用原生 `button`、`dialog`；提供可见焦点、Escape 关闭、键盘 Tab 顺序及状态文本，不以颜色单独传递信息。
- 动效仅用于 180–220ms 的 opacity/transform 过渡；尊重 `prefers-reduced-motion`。
- 桌面优先；在 920px 以下将树与表格垂直排列，表格使用横向容器避免压缩关键物料编码。

## 前后端方案

### 本交付（已完成）

独立 `prototype/index.html`：静态样例数据与浏览器端交互，用于确认编码规则、全量清单和导出字段；不读取/修改 InforCenter、数据库、颜色表或 SAP。视觉适配当前 DEV 中运行时采集的 Candidate 样式。

### 原厂菜单演示接入（待用户确认）

当前已定位到最小改动位置，但尚未修改：

1. 在 `PseBomMenu.menu` 新增 `TrialToMassProductionDemo` action，`ParentWebAtionName="BOMCommon"`，位于现有“收藏”后（建议 `Order="2600"`）。
2. 在 `PseBomMenu.dic` 增加“试制转量产”标签及本需求的阻断提示文本；不改动 `BOMCommon` 现有标签。
3. 新增独立客户化 JS（`TrialToMassProductionDemo.js`），只读取当前树行并执行车型编码正则校验；通过标准 `HoteamUI.UIManager.Popup` 打开演示清单页。该 JS 不调用写入服务。
4. 新增独立演示 page/dic，展示固定规则、全量清单和两列导出；不提供基线、物料另存/替换、颜色表或 SAP 操作。
5. 通过 `PSEBomFileRef.fileref` 加载新 JS。用户已确认该原厂最小修改范围；包内补丁尚未写入服务器。
